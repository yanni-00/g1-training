# 判定、产物与下一步

S7 / S8、tune 和 consolidate 共用。目标含义与修订仍按 [目标对齐规约](../requirement/goal-alignment.md)，暂停、终态及最终交付按 [执行规约](execution.md)。本规约收拢结果解释与保留规则，不新增状态系统。

## 判定与证据

每轮复用 `results.json` 存结构化结果，绑定 exp_id / gmTaskId，`verdict.md` 给出解释和出处；decision_log 仍是轮次登记 / outcome 真源，不另建判定账本。模板字段按实际任务填，旧记录缺字段记未知，不凭目录、文件存在或 passed 布尔值补造成功。

| results.assessment 层 | 只回答 |
|---|---|
| readiness | 软件 / 资产 / 平台接入在什么范围通过 |
| training | 实际注册训练是否完成；中断原因未知时保持未知 |
| behavior | 哪些冻结行为 / 质量门通过、失败或没有有效观察 |
| owner_acceptance | 用户接受哪个模型 / 控制 / 视频及哪些不足 |
| overall | 当前完整目标是否达成，或 owner 是否批准收束 |
| deployment | 部署链验收范围；不代替人工真机授权 |

各层使用 `status=passed / failed / incomplete / unknown / not_applicable`，附 scope 与 evidence 路径 / 字段。evidence 用本轮目录相对文件（或工作区 `.oma/…` 路径），字段定位写在 `#` 后；外部用户反馈先保存有出处的审阅记录再引用。`passed / failed / incomplete / not_applicable` 均须说明实际依据，不从其他层复制。摘要对缺范围 / 引用 / 本地文件的声明显示未知，但不独立核验文件内容能否证明该结论。训练 / 评估种子分栏，同一模型的多初态回放不称独立训练复现。

verdict 引用本轮需求版本、冻结协议、基线身份，逐门写“实际值 / 冻结标准 / 来源字段 / 判定 / 未覆盖项”；使用接入检查、实际行为、视频与 owner 反馈各自的证据，不用奖励或参考动作替代学习策略行为。没有完成有效协议的技术失败，不据此证伪算法。

`results.claims` 只登记影响决策的结论：`kind=fact / design_target / hypothesis / correction`，给出 statement、source（文件 / 字段或用户指令出处）和 scope。设计目标注明工程选择理由，不伪装实测；假设注明待验证 / 已检验范围。更正引用原结论及替代证据，保留原适用时点，不把旧推测继续当作有效事实。补充诊断不回改旧轮冻结门。

收束档位与证伪门只引用 AGENTS.md 的唯一表。基础设施故障、行政误停、评测无效、交付失败独立说明，不能仅因 CSV 中有“未命中”而统计成算法假设被证伪。缺数值来源就写未知，不填示例数字、估算或无数据的显著性结论。

## 文件生命周期：生成、消费、收尾

**先复用再新建**：配置进 config、结果进 results、解释进 verdict、当前视图由 resume 派生；普通进度留在现有日志 / 对话。只有独立消费者、冻结证据或恢复需要才新增持久文件，在既有 `results.artifacts` 说明用途。不逐次落盘状态快照、不为归档再造同义索引。

- 登记 / 回填优先 `oma decision … --file -` 读标准输入，或用已有 `--data`，不必生成 row / backfill JSON。平台只支持文件请求时，放入本轮 `work/`；仅清理本次明确创建的临时文件，在确认消费成功、任务 ID / 必要请求参数已写入权威记录后执行。失败 / 消费状态未知时保留用于恢复，不能只凭 exit code 或名字删旧文件。
- 一次性脚本也进本轮 work；准备、评分、摘要等跨轮重复逻辑参数化并进入项目已有工具目录 / 版本管理，以 config 作为参数来源，避免 prepare_rN / finalize_rN / write_* 每轮复制。独立算法逻辑仍保留，不硬塞入 OMA 通用工具。
- 原始证据和冻结输入保存一次，跨轮用路径 / 哈希引用。只有独立交付 / 保全确需自包含时复制快照。图、抽帧等可重建缓存按需生成，输入、命令和关键选择结果留存；不能从保留物恢复的内容不当缓存删。
- 当前入口只保留权威状态 / 派生摘要 / 通用工具；历史设计与 verdict 留在既有实验 / 设计目录，通过引用追溯。归档不改变冻结证据身份，不为减少文件数移动已被接受版本引用的旧路径。

必要产物按文件或成组目录登记；目录直接引用已有 manifest，不给每个中间文件建条目。每项包含 path、role、required（布尔）、rebuild（命令或 null）、dependencies（路径数组）、consumers（非空用途数组）、retention（保留条件）；目录另含 manifest。path / manifest / dependencies 以本轮目录为基准，`.oma/…` 以工作区为基准，可附 `#字段` 定位依赖。关键模型 / 配置 / 协议附实际 sha256 或已有 manifest 引用。

| role | 保留 / 整理规则 |
|---|---|
| input | 本轮冻结输入、源码 / 配置 / 模型 / 协议；跨轮引用注明身份，避免再存 source-* 副本 |
| raw | 原始日志、轨迹、回执及审阅证据；不可因有派生摘要而删除，保留必要原件 |
| derived | 评分、图表和诊断；注明输入依赖与重建方法，可合并重复摘要 |
| cache | 可重建工作缓存；写明何时失效与如何重建，不因命名为 cache 自动获得删除权限 |

先区分证据角色再整理，不能凭 JSON 后缀、相同字节或临时文件名批量删除。接受版本及依赖保持只读保全；模型包包含恢复其实际行为必需的参考、归一化、控制映射及源码 / 验收引用，不把 actor 导出称作完整在线控制器。

S8 收尾、轮转前运行 `oma doctor --artifacts --exp-ref {exp-id}`（可加 `--json`，报告留在终端，不再落盘）。仅枚举指定轮次：config.json / results.json / verdict.md 为约定核心文件；其余文件需被有效条目或带 manifest 的目录条目覆盖，检查必需文件 / 依赖存在性，并报告 work 残留。work 不长期归档；若失败材料确需留存，先将必要部分整理为本轮原始诊断证据并更新消费者引用，再检查。不能用把整轮目录声明成一个条目来绕过整理。

缺索引 / 身份冲突 / 读取失败记未知并返回非零；先解决缺项、恢复用途或明确报告阻塞，不伪报干净。旧实例不强制补造历史索引。此检查不阻止先回填真实失败 / 中断事实，不因整理而改 outcome；未整理完不得宣称轮次文件收尾完成。

doctor 只做本地归类 / 存在性检查，不验证 manifest 内容、证据正确性、恢复可行性或自动删除，也不能拦截任意外部写文件。实际清理 / 迁移前核对消费者与保全依赖，必要时验证恢复；依赖未知就保留并报告。历史库存单独审阅，不借规则升级批量清理。

## 诊断、续训与接受基线

先按实际证据区分接入 / 评测 / 原生策略行为 / 迁移回放 / 交付问题，选择最小鉴别检查。新训练必须有可检验假设；技术修复与算法变更分开，缺诊断依据不堆 reward / PD 或无上限延长。

续训提案在既有任务卡 / 登记 note 写明：父模型与可恢复状态、有限执行范围及依据、改善门、保护门和到点失败分支。中途趋势不代替最终门，环境 / 课程未恢复是混变量；不能只因奖励涨或任务 finished 自动续训。

无增益统计只纳入同目标 / 协议下可比较的有效算法轮；行政恢复、无效评测、中途诊断和重复看护不机械拼入。目标 / 协议 / 基线改变时分段记录，触发次数和增益标准来自任务卡预注册；缺少依据就报告缺项，不套统一 std 倍数或用单种子声称显著。

当前接受基线使用既有 `best.json` 引用，候选隔离保存；用同一冻结协议同时检查目标改善和原有功能 / 质量保护门。owner 接受不足、未覆盖能力与后续授权分别记录。候选有明显取舍、比较不确定或用户认为视觉相近时，保留原版 / 两版，不凭排名或某个标量自动覆盖。基线替换不派生部署授权。

将下一步及理由写入本轮 verdict：收束 / 暂停 / 有限续训 / 技术修复 / 鉴别诊断 / 新假设。已有授权内可继续；总目标未达而建议收束时按宪法给推荐与理由并等 owner 决定。任务 paused 就保留暂停，不由本规约恢复权限。
